## Contraste de las observaciones

1. mathjax.js crea handlers/document/retry y asyncLoad=null; esm.js instala loader sólo cuando falsy, convierte nombres que empiezan punto con base y pasa resto a import(file). setBaseURL cambia root. Fuente soporta loader genérico no cerrado, sin afirmar explotación o IO/red realmente observado. Desactivar paquetes TeX no certifica cierre de carga de fuentes/dependencias.

2. MathDocument.convert toma display/em/ex/containerWidth/scale/family/end y crea MathItem local; containerWidth=null pasa a80*ex. family sólo se aplica si correspondiente mtext/merrorInheritFont. setMetrics guarda unidades en objeto, no calcula métricas nativas de terminal. convertPromise encadena whenReady/handleRetriesFor y actionPromises, retorna nodo; no proporciona evidencia de deadline/cancel/Child/Job/EOF/reap. La documentación [API directa](https://docs.mathjax.org/en/latest/server/direct.html), identificada4.0, describe el flujo y rangos dinámicos; no se toma su containerWidth infinito como comportamiento probado4.1.3.

3. TeX.compile atrapa TexError, marca parseOptions.error y llama opción formatError; otros errores se relanzan. Default formatError construye error con mensaje truncado a primera línea, id y latex; la expresión también se guarda en atributo math. MathDocument.compileMath/typeset tienen rutas de nodoerror/diagnóstico y rethrow retry/restart. Un SVG o Promise fulfilled no prueba éxito semántico. No se ejecutó fórmula inválida, no se eligió paquete/dialecto ni clasificación final de errores.

Observación adicional propia: base csUndefined lanza TexError, pero NoUndefinedConfiguration instala fallbackmacro que crea mtext con el nombre literal y colorred por defecto; ese handler no lanza TexError. No implica que todos errores o paquetes sigan esa ruta. El futuro adapter debe medir perfil/corpus y distinguir ambos casos, sin asumir que cada comando indefinido llegará a formatError. Es un límite complementario, no contradicción del texto congelado ni nuevo defecto del producto.

4. SVG.createRoot obtiene bboxw/h/d/pwidth. createSVG usa W/Hclamp, currentColor, escalaYnegativa, vertical-align de−d y viewBox; pwidth guarda data-mjx-viewBox, elimina viewBox, cambia width y transform según ex/x_height. Declaraciones protected createRoot/createSVG confirmadas en TS previamente capturado, sin elevar sus funciones MJS a API pública estable. No se deduce tamaño píxel, baseline visual, rasterización, autosuficienciaSVG o equivalencia de fuentes desde atributos.

5. SVG localcache se limpia/reasigna ID y agrega defs al SVG; globalcache se busca en documento y se introduce con pageElements. reset de SVG llama clearFontCache. MathDocument.reset permite conjuntos processed/inputJax/outputJax; clear llama reset con defaultprocessed y vacía mathlist. TeX.reset limpia parseOptions/tags. Estos conjuntos y los handlers/globalmaps son diferentes: no aislamiento/fugas/cancelación/cierre total probado por un clear. LiteBase tiene métodosstub de medidas; LiteAdaptor hereda NodeMixin externo a selección, por tanto no inferir valores efectivos/concurrencia/recursos del adaptor final a partir de esos stubs.

## Matriz y disposición

MA01 PASS identidad/bytes/publicado; MA02 PASS contraste de convert/error sin runtime; MA03 PASS atributos y unidades explícitos pero métricas/adapter pendientes; MA04 PASS imports genéricos y carga incompleta reconocidos; MA05 PASS ámbitos cache/reset, sin cleanup inferido; MA06 PASS zeroexecution/instalación, dependencia de validación futura conservada; MA07 PASS evidencia congelada sin cambios y ningún fallo propio de este control.

Los hallazgos del candidato son accionables para el refinamiento futuro y no afirman una integración aceptada. No se propone aquí protocolo/quota/dialecto/permisos/versionNode por preferencia. Siguiente gate real: contrato de loader cerrado o preloading que conserve cobertura, métricas/baseline/errorcache tipados, inventario recursos/contextos y supervisor físico con original identidad/cancel/deadline; posteriormente ejecución fría/corpus/fórmulaerror/retries/cancel/reap y render independiente. Ninguna de esas garantías está acreditada por esta revisión de fuentes. RV303/501/QA y engine/runtime siguen abiertos.
