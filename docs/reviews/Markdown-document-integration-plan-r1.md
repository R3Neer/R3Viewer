## Contraste por escenarios

- **Entidad/escape frente a fuente:** un Text decodificado `&` cuyo token es `&amp;` no puede convertirse en BorrowedRange ni en mapping escalar exacto. El plan exige comprobar igualdad para préstamo, OwnedDecoded para transformación y ExactToken/EnclosingToken para procedencia. Source íntegra y búsqueda documental tienen dominios distintos; un salto desde un hit puede indicar el contenedor. No se afirma falsa identidad de bytes.
- **Valor transformado frente a archivo:** texto que llega por pipeline con metadata de una ruta no reabre esa ruta ni obtiene cwd como base de nota. Literal/pipeline sin base dejan un destino no resuelto. Un Nu record no se convierte universalmente en Markdown. Esto conserva entrada y tipos actuales.
- **Wiki y contexto:** `![[Manual.pdf#page=3|300]]` conserva condición de embed, fragmento físico 1-based y opciones; no se trata como link ordinario ni se decide basename ambiguo. Wiki/math dentro de código/HTML contextual no activa recursos por regex global. Callout personalizado mantiene fallback, y headings/bloques/duplicados requieren índice/política posterior. No se atribuye esa resolución al PASS del parser.
- **Red y HTML:** URL explícita permite obtener ese documento; imágenes secundarias siguen referencia hasta acción. Base local y URL final/baseHTML son diferentes. DOM y `from html` siguen separados del documento visual, conversor opt-in; tareas/formularios muestran estado y no envían ni editan. El plan no inventa autorización persistente o flag de autocarga.
- **Parser bloqueado/salida tardía:** constructor/next de pulldown se llevan a proceso antes de parsear; source128MiB permanece. Respuesta final con generación/hash/origen, framing acotado, EOF sin trailing, cancel/stale y reap preceden publicación. El ejecutable experimental/Python no se adopta como supervisor de producto y 32KiB del gate no se convierte en cuota de fuente del producto.
- **Reflow y recursos:** cambiar viewport no cambia nodeId/hits/history dentro del snapshot. Nuevo reload sí cambia identidad. Fragmentos usan Unicode admitido antes de Ratatui. Una fórmula inline exige baseline/ascent/descent y tamaño real; no se sustituye por una imagen debajo del párrafo. TUI/inline comparten semántica y redirección sigue textual. Errores locales preservan recurso/fuente sin abortar el documento entero.
- **Browser y procesos:** GIPC ActiveProcessLimit2 cubre controlador+codec del gate, no concede un tercer proceso Chromium. El plan exige contrato propio de Mermaid/MathJax/browser antes de conectarlos. La prueba visual final sigue siendo documento mixto, scroll/resize/exit y protocolos sin consumir teclas; ConPTY/fallback no acreditan esa aceptación.

## Fronteras todavía no aprobadas para implementar

Estas son pendientes explícitas de las etapas 1–4, no críticas al plan macro ni una exigencia de diseñar ahora todo el producto:

1. Wire/arena concretos: catálogo de tipos/perfiles, validación de IDs/aristas/rangosUTF8/generación/hash, discriminantes/longitudes/framing, control de counts y ciclos, End+EOF, errores IO de writer/readers antes del único commit. Modelos de datos R3ST y gráfica GIPC son referencias; no confundirlos con un protocolo documental ya definido.
2. Ledger/source handoff: fuente128MiB, arena64MiB, millón de nodos, depth64 y transporte128MiB son candidatos, no suma aprobada. Contar source/copies/capacity, arena/cooked, receive/write/queues, old+new y layout/cache; preadmitir antes de reservas; probar exact/+1/fallos y quién retiene source en cada fase. No copiar JSON completo por conveniencia.
3. Contención/cleanup: `worker_process.rs` actual fija Job512MiB por proceso, KillOnClose y asignación, pero no acredita aquí readback de contención efectiva ni presupuesto agregado. El requisito del plan de validar antes de admitir fuente necesita diseño/prueba nuevos, incluyendo setup parcial, cancel, timeout, error tardío y Pending/Failed bloqueando la reutilización. Unix sigue pendiente nativo.
4. Selección del adaptador/UX de documento: concretar `--format`/extensión real/literal-pipeline, Fuente↔Documento, query/hit/history/anchor y fallback de parser/cuota sin cambiar resolución de lenguajes o flags por inferencia. El plan remite esta frontera al refinamiento y AE sobre consumidores reales; no se aprueba una CLI nueva implícita.
5. Resolver y composición gráfica: políticas Obsidian de anclas/alias/dimensiones/raíz/ambigüedad/ciclos, recursos con identidad de contenido/motor/opciones/cache y servicios con bundle/licencias/aislamiento. Render de PDF físico no implica que su extracción semántica Unverified quede resuelta. La aceptación completa RV-301/302/303/305/306/307 y G2 permanece según sus propios criterios.

El orden propuesto exige refinar/revisar cada frontera antes de editarla, y coordinar Cargo/main/lib después del freeze del incremento activo. Es compatible con arquitectura por capacidad: documento textual puede avanzar antes de gráficos, sin convertir ese corte en final Markdown enriquecido. No hay hallazgos accionables pendientes dentro de este plan; toda aprobación futura de código/layout/wire necesita candidato exacto y evidencia independiente nueva.
