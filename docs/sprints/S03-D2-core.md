## Proceso y protocolo

Un StructureFormat privado Toml/Json se propaga desde selección hasta Request y Message::Init. Versionar R3ST a2; Init incluye selector, Begin devuelve el mismo selector y el padre valida igualdad además de generación/id. No negociación con workers de otro paquete: ejecutable propio exacto. El controlador, Job, reap, pause/resume de sintaxis, lease, deadlines y publicación son los existentes.

Extraer únicamente transporte stdio/lease/output del actual toml_worker a structure_worker. El main despacha un único argumento privado --structure-worker; no CLI pública nueva de workers. TOML conserva project; JSON aporta json_worker::project con igual retorno. El lease rechaza frames tras SourceEnd en el reader. Failure añade InvalidJson y UnicodeRepresentation sin confluir con InvalidToml. Ninguna interpretación invoca una ruta ni un comando Nu.

## Arena y lexemas

Añadir clases Null y JsonNumber a StructureKind y discriminantes IPC versionados; Null exige lexema rawnull y JsonNumber lexema raw validado por proyección. No convertir números a enteros/flotantes. Mapping/Sequence/String/Boolean permanecen. NodeSpec.locations contiene spans raw completos UTF8, incluyendo comillas para keys/strings y delimitadores para contenedores. TextRef apunta al interior original solo si ese interior equivale exactamente al cooked; si hay escapes, append_cooked por chunks y se presta cooked. Nunca usar puntero de next_str como posición original.

Índice TOML de declaraciones permanece vacío para JSON. Un miembro no es Assignment ni ruta dotted: ubicación contigua derivable key.start..value.end, comprobando ambos spans y límites; EntryRef puede prestarla sin nuevo vector de declaraciones. La navegación usa ordinal incluso para keys iguales.

Duplicados se comprueban en el modelo validado, tanto hijo como padre. Después de validar UTF8, claves y grafo, finish ordena temporalmente IDs de entradas de cada Mapping por texto de clave decodificado, sin clonar keys ni cambiar las entradas originales. Usar heapsort fallible propio sobre un único vector ID, con callback cancel/deadline antes de cada paso de sift/intercambio. Comparador de textos prestados lexicográfico en bloques de hasta4096bytes, check callback entre bloques y desempate ordinal original para determinismo. El recorrido de grupos posteriores compara únicamente texto decodificado con los mismos bloques/checks; NO aplica desempate ordinal para igualdad. El ordinal se usa exclusivamente como desempate durante ordenación: a/\u0061/a forman un único grupo y cuentan2extras; Result aborta toda construcción antes de publicar Summary. No usar sort_unstable monolítico en padre ni confiar en Job del hijo para este trabajo. Padre finish_with recibe status/deadline del controlador; hijo callback cancel y deadline externo de proceso. Vector previamente cargado a presupuesto y reutilizable; ningún otro scratch de ordenación. Comparar adyacentes detecta equivalencia exacta y suma ocurrencias posteriores a la primera. Un vector scratch reutilizable acotado carga su capacidad al presupuesto antes de reservar, junto con scratch de DFS y caller vivo. Resultado DuplicateSummary { extra_occurrences, first_key_span } constante; se calcula localmente, no se confía en un contador del worker. No array de advertencias ni hashset ilimitado. La primera ubicación es el mínimo byte raw de las ocurrencias repetidas, determinada en el grupo por ordinal original, no por orden del sort. first_key_span None si contador0.

La metadata constante se incluye en persistent_bytes. Summary se devuelve mediante préstamo/copia acotada desde Structure y da una advertencia discreta Ready/inline. Nunca elimina una ocurrencia. TOML válido obtiene contador0. Si los buffers exactos de detección exceden presupuesto, fallback de fuente íntegra; no saltar detección para publicar. El adaptador de archivos usa vista de entradas para objetos, sin introducir flatten/table nuevo; si futuras tablas necesitan unicidad deben consultar el objeto específico, no asumirla por la etiqueta.

## Proyección JSON

Dependencia privada vendorizada Jiter0.17.0 fijada, original+licencia+VCS+hashes, adaptación NumberRange ya aprobada que elimina límite4300. Registrar diff exacto; no alterar NumberInt/Float ni usar next_value/JsonValue/map. Pull next_object_bytes/next_key_bytes preserva todas las ocurrencias. next_number_bytes conserva lexema, finish comprueba EOF exacto tras whitespaceJSON. Raíz cualquier valor. Pila de llamadas acotada64 con comprobación antes del siguiente nivel; padre vuelve a validar profundidad lógica y1M nodos/aristas.

Capturar posición mediante current_index/peek y whitespaceJSON. Para una clave, localizar el token antes de next_object_bytes/next_key_bytes según delimitador esperado ({ o coma), sin alterar el cursor principal; esas APIs consumen tanto clave como colon y siguen siendo la autoridad de estructura. El preflight local obtiene rango prestado completo y verifica comillas, UTF8, controles/escapes y surrogates. Para el cooked, crear un Jiter local sobre ese rango raw completo con comillas, next_str+finish y append_cooked por chunks antes de perder el préstamo; nunca next_str otra vez en el cursor principal. Stringvalue usa preflight y APIprincipalnext_bytes, con mismo decoderlocal para cooked. JSONkeya.b sigue una única clave. Localizador no acepta/repara delimitadores: Jiter principal confirma colon/coma/cierre/EOF. Verificar spans contra fuente, fronteras UTF8 y comillas. Bytes raw de strings/keys prestados por Jiter solo cubren interior; el spike aprobado valida la derivación start-1/end+1. next_str decodifica sin replacement y conserva el raw completo por rango independiente. Surrogate aislado provoca UnicodeRepresentation, no InvalidJson; errores de escape distintos siguen InvalidJson. La fuente exacta Jiter string_decoder.rs:parse_escape distingue LoneLeadingSurrogateInHexEscape para low aislado/segunda pareja incorrecta, pero high aislado puede dar UnexpectedEndOfHexEscape. Antes de consumir un token string/key, un escáner local prestado comprueba cierre, controlesraw y escapes JSON con u4 bien formado, registra surrogate aislado y conserva rango exacto; sin construir cooked ni recorrer todo documento. Una secuencia high sin low o low aislado en un token léxicamente válido da UnicodeRepresentation; token con escape/control/cierre inválido da InvalidJson. Jiter sigue validando estructura, colon/comas/EOF y decodificando strings representables. Esta comprobación localizada no afirma validez de toda gramática ni busca mensajes de error por texto.

Entries buffers propios se reservan con budget guard. Objetos/arrays no conocen su longitud anticipada: crecer de forma controlada y actualizar scratch vivo antes de crecimiento de arena; liberar cada buffer tras set_entries, incluyendo capacidad viva del IntoIterator. Tape/cooked temporal interno Jiter es transitorio del parser bajo Job512MiB; source128MiB y transporte acotado permanecen separados. Deadline del proceso limita llamadas monolíticas Jiter del hijo; detección de duplicados y comparación de claves largas se comprueban en bloques/pasos en ambos procesos; un token aceptado por gramática puede degradar por presupuesto/deadline, conservando fuente.
