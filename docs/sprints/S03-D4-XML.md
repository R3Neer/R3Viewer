## Procedencia y candidato

Leídos docs/spec/REQUISITOS.md (F06/F09/NF03/NF05/NF06 y requisitos57–58/131/201), docs/spec/CONTRATOS.md y docs/BACKLOG.md de D:/Tools/R3Viewer. La propuesta reutiliza el contrato de entrada/controlador TOML/JSON/YAML; no añade un conversor XML→tabla Nu.

Fuentes normativas: [XML1.0 Fifth Edition](https://www.w3.org/TR/xml/) y [Namespaces1.0 Third Edition](https://www.w3.org/TR/xml-names/). XML distingue texto, elementos, referencias, CDATA, comentarios y PI; exige atributos únicos aunque su orden semántico sea irrelevante. La vista propuesta conservará también ese orden lexical para inspeccionar fuente. Namespaces distingue nombres expandidos URI/local del prefijo: default namespace afecta elementos sin prefijo, no atributos sin prefijo; duplicados por nombre expandido son ilegales. Estas reglas no convierten a R3Viewer en validador DTD/XSD. [XML §3](https://www.w3.org/TR/xml/#sec-logical-struct), [Namespaces §6](https://www.w3.org/TR/xml-names/#Applying).

## Propuesta observable X01–X09

**X01 Entrada.** Archivo local real .xml en Auto/Code conserva fuente inicial y ofrece Estructura. Literal/stdin/Nu String o ByteStream String requieren --format xml para interpretación; --language xml selecciona sintaxis únicamente. Unknown no se adivina como texto; tipos Nu no textuales conservan el contrato vigente, sin serialización implícita. Redirección fuente predeterminada preserva bytes de entrada admitida; estructura explícita produce representación humana etiquetada, no serializer XML ni tabla inventada. No cambiar open/from xml de Nu ni asociar automáticamente SVG/HTML a este lector estructural.

**X02 Perfil de entrada.** Proponer inspector de serialización XML1.0 + Namespaces1.0, documento finito con un único elemento raíz. XML declaration opcional version1.0; versión explícita distinta produce Unavailable de documento completo. Espacios del prolog/epilog, declaration, comentarios y PI se conservan en orden. Vacío, dos raíces, texto no whitespace fuera de raíz, tags desparejados o truncados producen fallo completo. Nada de reparación HTML, fragmentos múltiples, XML1.1, DTD/XSD validation o promesa de conformidad XML processor completa. Nombre/QName/Char y restricciones namespace requieren gate explícito; una sucesión de eventos no constituye prueba de well-formedness.

**X03 Forma neutral.** Document con hijos ordenados; Element con QName original, nombre expandido conocido (URI/local), atributos/declaraciones namespace en orden lexical y contenido hijo en orden textual. Atributos y namespace declarations tienen identidad ordinal independiente del nombre mostrado. Children distinguish Text, CharacterReference/PredefinedEntityReference, CDATA, Comment, PI; Declaration y DocType son nodos de inspección en Document. Empty `<e/>` conserva marca lexical frente `<e></e>` sin convertirlo en null; ausencia de texto no equivale a string vacía explícita. Elementos hermanos repetidos nunca se agrupan en dict. Atributos duplicados lexicales o expandidos producen Unavailable, no last/firstwins; fuente sigue accesible íntegra. Namespaces anidados/rebinding/restauración se resuelven por scope, conservando además la escritura xmlns. No resolver URI ni percent-decode/normalización de namespace URI, no visitarla como URL.

Ejemplo `<p b="2" a="1">uno <i/> dos&amp;<![CDATA[tres<]]><!--c--><?x y?></p>`: atributos b,a; hijos Text("uno "), Element(i,empty), Text(" dos"), Reference(raw="&amp;",decoded="&"), CDATA("tres<"), Comment("c"), PI(target=x,data=y). La representación mantiene sus ordinales y fronteras. No unir texto a través de markup ni perder espacios por trim. Este árbol de inspección no es un DOM persistente completo ni detalle de arena aprobado.

**X04 Texto y referencias.** Conservar raw completo y cooked cuando el perfil lo admite. Texto/CDATA aplican EOL XML1.0 CRLF/CR→LF; atributos aplican normalización XML1.0 de CDATA sin información DTD, distinguiendo whitespace literal frente referencia numérica a whitespace. Ninguna conversión numérica de valores ni normalización Unicode. CDATA no interpreta `&amp;`. Resolver únicamente las cinco entidades predefinidas y referencias numéricas válidas para Char XML1.0; rechazar NUL, ESC/U001B, surrogates y valores fuera de rango, tanto literales como referencias. U009B legal en XML1.0 se presenta con SafeText pero búsquedas comparan cooked original. No inferir tipos bool/int/null de texto.

**X05 DOCTYPE y recursos.** Proponer DOCTYPE como metadata lexical inerte, con aviso claro de que DTD no se procesa; no defaults de atributos, entidades declaradas, parameter entities, validación ni expansión. Ningún recurso SYSTEM/PUBLIC, namespace URI, PI xml-stylesheet, XInclude, schemaLocation o xml:base causa acceso a red/archivos, ejecución o carga de constructor. Una referencia custom en contenido o atributo, aun declarada en subset interno, produce Unavailable documento completo con diagnóstico específico «referencia de entidad no soportada por este perfil», no «XML inválido» automáticamente. Esto evita fingir cooked que no existe o certificar declaración de entidad sin procesar DTD. DOCTYPE mal delimitado o posición inválida produce fallo; estructura interna no validada debe quedar explícitamente fuera del alcance de inspector. Gate futuro debe probar scanner de subset con quotes, brackets, comentarios y `>` internos antes de prometer rawspan completo. Esta política es restricción del producto: XML processors normativos tienen obligaciones sobre declaraciones internas que esta vista no cumple. [XML §5.1](https://www.w3.org/TR/xml/#proc-types).

**X06 Rangos fuente.** SourceSpan UTF8 start0/endexclusive contra source original, validado por límites y fronteras. Element span completo desde apertura hasta cierre; empty incluye `<.../>`. Text usa bytes lexicales antes de EOL/cooked. CDATA, Comment, PI, Decl y DocType incluyen delimitadores completos. Attribute seleccionable tiene span de todo `QName = quote...quote`, y subspan rawvalue incluye ambas quotes; QName/subspan value se publican solo si acreditados. Comentario posterior fuera del atributo no se incorpora. Namespaces mismo trato lexical. Nada de spans reconstruidos serializando cooked. BOMUTF8, CRLF, CJK/nonBMP/combining, refs, quoted `>` y delimitadores son gate obligatorio. Si rango no puede acreditarse, fallar representación de forma completa o declarar None en una propiedad realmente sintética, sin rango inventado.

**X07 Búsquedas.** Fuente busca raw; Estructura busca nombres originales/local/URI conocidos, cooked de atributos y hojas Text/CDATA/Reference y metadata de Comment/PI/Decl/DocType con dominio visible etiquetado. Proponer búsqueda por nodo, sin búsqueda textual concatenada que cruce nodos/reference/markup; delimitar esta limitación en ayuda. n/N wrap y coordenadas cooked↔display usan el mecanismo JSONR2 sin confundir glifo literal U241B con placeholder de ESC (ESC inválidoXML1.0 sirve como fallo; usar C1U009B para caso válido). `o` salta al raw completo de nodo/atributo/token seleccionado, y Tab conserva cada consulta/posición independientemente. Alias XML no se inventa; ID/IDREF no navega targets por DTD sin validación.

**X08 Límites y lifecycle.** Reutilizar source128MiB, nodes+edges1M, depth64 de elementos excluyendo wrapperDocument, persistent+ownscratch64MiB incluyendo attrs/namespaces/text/índices/spans/cursor, childJob512MiBWin, deadlines2sTUI/5sinline y ownership del controlador. Nodos atributos/metadatos/wrappers y todos edges cuentan; no cuota gratis ni ruta masiva por nodo. Namespace stack/lookup y revisión de duplicados expandidos también presupuestados. Ninguna expansión de entidades. Parser/perfil/representación/presupuesto/deadline→Unavailable latched+Fuente completa0+diagnóstico específico; no Ready parcial. Building cancel→NotRequested/manualretry; q0/C130 restauran terminal y reap solo hijos propios. No simultaneous syntax/structure worker ni resultado obsoleto. QA/contención Unix sigue pendiente.

**X09 Aceptación futura.** Corpus sintético futuro para entradas/redir/Nu, texto mixto y whitespace, attrs ordenados+dup expanded, namespaces scope/reservedprefix/unbound, CDATA frente entities, PI/comment/DOCTYPE inertes, encoding/version, exact spans, errores tardíos whole-document y controles/glifo/cooked. Límites64/65 y memoria propia antes de calloc/copy; cancel/reap/timings separados y regresión TOML/JSON/YAML. No suite completa ahora; gates de contrato→parser/offsets→detalle→implementación→adversario→AE, sin cerrar visual/VT/Unix por builds.

## API y riesgos que el spike deberá resolver

[Reader0.42](https://docs.rs/quick-xml/0.42.0/quick_xml/reader/struct.Reader.html) espera UTF8, read_event_into presta buffer reutilizable y buffer_position marca byte posterior al evento; error_position aporta posición de diagnóstico. La transcoding opcional via DecodingReader destruye la equivalencia directa con offsets originales: excluirla inicialmente. Proponer admitir únicamente entrada UTF8 válida, declaration ausente o encodingUTF-8 case-insensitive y BOMUTF8; declaration de otro encoding→Unavailable perfil, no transcodificación. La frontera de lectura vigente para bytes noUTF8 continúa con su diagnóstico actual, sin prometer Source0 textual inexistente. Spike necesario antes de afirmar BOMoffsets.

[Event0.42](https://docs.rs/quick-xml/0.42.0/quick_xml/events/enum.Event.html) separa Start/End/Empty/Text/CData/Comment/Decl/PI/DocType/GeneralRef/Eof. No usar read_text/read_to_end para esconder nodos ni Serde de para dict. Un Eventowned implica asignación nueva; retener rangos y cooked mínimos con admisión previa. Guardar antes/después del evento es hipótesis a contrastar para BOM, markup, texto y refs; no restar eventpayload.len a ciegas porque faltan delimitadores y hay normalización.

[Config0.42](https://docs.rs/quick-xml/0.42.0/quick_xml/reader/struct.Config.html): activar comprobación comments y endnames; mantener danglingamp/unmatchedends rechazados y Empty sin expansión; trim_text_start/end false. enable_all_checks solo documenta comments/endnames, no certificación general. Espacios de closingtag pueden ser legales, no desactivar trim_markup_names sin entender endname comparison. Gates adicionales de rootcount, declaración/doctype posición, Name/QName/Char, attributessyntax y namespace restricciones son imprescindibles; no atribuirlos gratuitamente al parser.

[Attributes0.42](https://docs.rs/quick-xml/0.42.0/quick_xml/events/attributes/struct.Attributes.html) es iterator; verificar orden y cada error, sin filter_map de Result ni desactivar with_checks. [Attribute0.42](https://docs.rs/quick-xml/0.42.0/quick_xml/events/attributes/struct.Attribute.html) expone QName/value raw y normalized_value; no ofrece en esos campos rango completo quote/equal/whitespace. Extraer spans exactos del starttag requiere adaptación lexical o API probada, especialmente Cowowned y valores normalizados; offsets de punteros no son contrato general. Duplicados por nombre expandido requieren evaluación propia aunque iterator compruebe QNamelexical.

[NsReader0.42](https://docs.rs/quick-xml/0.42.0/quick_xml/reader/struct.NsReader.html) gestiona declarations y read_resolved_event_into resuelve Start/Empty/End; atributos requieren resolver con reglas distintas y snapshot mínimo de URI antes de modificar scope. Probar cuándo sale namespace de End/Empty y límites del resolver. Resolver namespace no valida por sí solo todas las restricciones reservadas/uniqueness.

[BytesRef0.42](https://docs.rs/quick-xml/0.42.0/quick_xml/events/struct.BytesRef.html) resolve_char_ref distingue referencias numéricas y retorna char, pero declara que no impone WFC LegalChar (salvo NUL rechazado); validar Char XML1.0 explícitamente, también dentro attribute normalization. [BytesText0.42](https://docs.rs/quick-xml/0.42.0/quick_xml/events/struct.BytesText.html) xml10_content aplica EOL normalization y puede asignar: presupuestar primero, distinguirlo de expansión de GeneralRef. Ejemplos de README no bastan para afirmar equivalencia completa del cooked.

Riesgos de viabilidad abiertos: token único grande puede hacer crecer buffer/stack/namespace storage antes de límite propio; interfaz pull no garantiza preallocation control. Parser gate necesita verificar estas asignaciones, exposición de offsets exactos y DTD scanning, cobertura de well-formedness/perfil, licencias y MSRV, sin iniciar detalle de arena/producto hasta aprobar este contrato. La investigación documental no acredita ninguno de estos gates.
