# D2c — publicación, lector y resize: delta de ejecución
2026-10-10. Propuesta privada sobre el Pump completo actual; no aceptación ni cuotas nuevas. Mantiene contrato canónico D2c, todos C01–16/R2/E y fixtures. D3/D4 posteriores siguen separados; esta corrección no depende de overlay color.

1. **Problemas concretos actuales.** Pump extrae `reader.next_event()` sin admisión Work; sus callbacks native usan `|_| true`; resize cambia `self.geometry` antes del flush y no prepara el owner para la nueva área. Son superficies de ejecución pendientes, no garantías del inspector/Source históricos. El lector R4 tiene P02 real (cancel foreign), así que se compondrá R5 exacto sólo tras aceptación; getters puros actuales no lo cierran.

2. **Ingreso real.** Añadir método fallible `next_event_with_work(&mut self,&mut DocumentWork)->Result<Option<SeqEvent>>`: preadmite `known_next_event_work_bytes` compilado antes de leer/stage/take. Mantener `next_event` histórico intacto. Pump retiene `ingress_operation: Option<SessionOperation>` y ack monotónico del último evento interpretado. La operación creada/admitida para ese evento pasa a captura, worker, chrome y renderer de su intención; no se crea otra allowance en `begin_request`/redraw para la misma intención. `queued` mueve `(Request,SessionOperation)` completo, no clona ni reduce spent. Release se admite/consume en orden y se ignora semánticamente; q editor/Esc panel siguen reglas reales. El control atómico de q/Esc sólo pide detener/posponer preparación, nunca inventa salida. CtrlC usa el Arc original retenido verificado por R5. Busy/Pending físico conserva el input/cargos; ScopePending conserva evento en head/queue y no llama take. Un nuevo evento puede describir una nueva operación semántica; reintentos/candidato de esa intención conservan su operación original. No se usa esto para renovar una operación color existente.

3. **Prueba de actualidad antes de IO.** `SessionRenderPlan` preadmite visitas compiladas del lector y del contexto de validación para las tres llamadas máximas del callback cerrado de `draw_session_transactional`; no se cobra toda queue como scan ni se lee cuerpo UI fuera de ese bound. La callback comprueba cancel original, binding/geometry/revisión de la intención y ausencia de otro evento aceptado aún no interpretado. `accepted_pending` puede stage head pero no extraerlo; sus lecturas están preadmitidas. Un veto preIO devuelve Stale/control-defer, no error fatal1 ni falso rollback visible. No hay lectura de eventos ni allocation entre flush válido y commit infallible.

4. **Retención del candidato.** Añadir `ViewportCommitGuard::cancel(self)->PreparedState` como transferencia cerrada del mismo Box real sin copiar/clonar layout/Flow ni cambiar current; sus cargos de guard se destruyen físicamente. Pump mantiene una variante owned `ReadyDocument`/`ReadySource` con su resultado, operación y efecto cuando hay veto preIO. Los cuerpos de esas variantes/Option son parte de sizeof Pump/Active y se admiten antes construir el owner. Un intento más nuevo reemplaza/cancela esa candidatura sólo después de capturar su input real; fallo/pending conserva current y los recursos necesarios de la candidatura anterior. No se vuelve a ejecutar un resultado recibido con allowance nueva.

5. **Loading inicial.** Un DocumentView construido del primer resultado aún no publicado se mantiene como candidato `Initial`, separado de `self.view` confirmado. No se instala como current para justificar scopes/history/ColorAdmission. Al procesar un evento diferido sobre Loading, q/CtrlC/editor/panel conservan su semántica existente; navegación destinada a Documento se prepara contra el candidato owned real por préstamo/descriptor cerrado del mismo documento/context/metadata. Sólo el resultado de la intención vigente puede publicar el primer frame; si no hay revisión que afecte body, el candidato inicial puede revalidarse con su operación retenida. Timeline permanece vacía hasta primer flush confirmado. No se pierde T por un veto ni se renderiza una vista invisible como si fuera current.

6. **Geometry candidata.** El extent se toma del descriptor/prepared real (`session_extent` y Geometry) con getter prestado, sin reinterpretar left como x. `self.geometry` sólo cambia junto con vista/pane/history después del flush. Redraw/editor anteriores usan geometry confirmada. Fuente toma geometry del SourceViewportPrepared real y conserva source binding/selection/model owner. No crear otro SourceScope/Box para resize.

7. **Preparación framework y primera IO.** Separar dentro BudgetedTerminal la reserva/preflight de geometría (sin IO) de su aplicación al frame. Un permit opaco liga área candidata, área/identidad owner previa y capacities reales; reservas fallidas conservan primera capacidad físicamente ganada y actual readback. Mismo área es noop estable. Reserva/resize/reset/readback/formatter/control efectivamente usados se cobran al mismo SessionOperation, antes paso/alloc, con sumas checked y métricas reales; ningún perfil nuevo ni dato raw oldheap por caller. El plan native se prepara contra esas capacidades reales y todos los cargos old+new siguen retenidos.

8. **Aplicación geometry + draw.** Último check original/cancel/reader ocurre antes de la primera IO de resize/clear. Después de comenzar IO no se devuelve un rechazo que afirme current visible intacto: error/cancel observado después se clasifica partial/poison y restaura terminal. El camino admitido resize/clear + apply_buffer + flush usa el mismo permit y no lee nuevos eventos entre primer IO y publicación; sólo tras flush se comprometen geometry/view/pane/timeline. El mirror previo y cargos no se retiran anticipadamente. Fallo preIO deja confirmados iguales. El cambio upstream/vendorizado mínimo necesario se inventaría con procedencia; no tocar registrycache ni cambiar Legacy resize semantics.

9. **Work y fallback.** Session8MiB/Source512KiB/Frame256KiB/Consumer1MiB/Actor64MiB/Framework2MiB/Symbol16KiB permanecen. Capturas/reader/guard/header nuevos son cuerpos compiled y lectura/copia real, no64 ilustrativo. Work resize puede provocar FAIL real: conservarlo y medir por componente; no bajar cargos ni añadir allowance al fallback. Reference sólo usa mínimo retenido/admitido de esa MISMA operación y se publica transaccionalmente. Si no cabe, conservar current con causa visible; no declarar dense resize funcional hasta medir. Source spent se exporta una vez.

10. **Evidencia prospectiva de ejecución completa.** Reutilizar los controles E03/E04/E05/E08/E09/C01–16 y SO/FT/RH previos; añadir sólo observación de rutas antes faltantes: evento llega después de progreso real/preflight y antes IO (q normal0, q editor literal, Esc panelback, CtrlC130, scroll/resize latest); candidato initial y current reales, sin segundo modelo; cancel/Limit/stale preIO conserva current y timeline; partial resize/flush poison+restore; 80x24→120x40→80x24 con Source selection y Document TableResume; exact−1/exacto de costo agregado observado bajo mismo allowance; no clear al mismoRect; new event during ack no perdido; Pending retiene owner/reader/candidato y restore antecede reap. Todo por run_markdown/probe/worker y ConPTY reales, no mocks que acrediten pump. Geometry0 usa hook sobre la misma API si host no admite0 físico, con recibo0IO y limitación expresa.

11. **Freeze.** Antes outputs nuevos guardar inventario compiled, fixtures/oráculos/ejecutable/worker/env y fuentes completas; conservar fallos anteriores. Final cargo fmt global y Clippy alltargets capturan exit explícito. No cerrar D2c por estos helpers: entrega única sesión completa con todos contratos anteriores y aceptación ajena.
