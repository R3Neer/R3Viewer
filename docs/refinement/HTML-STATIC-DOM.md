Companion separado `nu_plugin_r3viewer_html`: dos PluginCommand REALES `from html` y `from htm`, con implementación compartida, entrada string/binary/ByteStream textual o de bytes y salida record. Nada/list/record arbitrario devuelve error de tipo; empty string es documento HTML vacío, no ausencia. Activación temporal explícita `nu -n --plugins '[ruta-al-companion-opcional]'`; empaquetarlo no lo activa. El companion encoder y `use r3viewer.nu` no declaran conversores. ## Modelo y salida propuesta

Un mismo núcleo produce `HtmlProduct{source, origin, dom, options, diagnostics}`; conversor y visor consumen el mismo resultado validado. Parsear documento completo, sin concatenar eventos append-only ni serializar Markdown. Nodes tienen ID local estable al propietario/snapshot y tipo Document, Element, Text, Comment, Doctype, ProcessingInstruction o DocumentFragment. Element guarda QualName{namespace,local,prefix}, lista ordenada de atributos QualName/value, enlaces de parentesco/hijos y referencia separada a template_contents cuando procede. Text conserva caracteres y posición mixta; no agrupar por tag ni descartar espacios. Adjacent text se fusiona conforme a TreeSink. Operaciones de detach/insert-before/reparent modifican el árbol, con IDs sin reutilización durante parsing. Quarantine comprueba índices, tipos, ciclos, padres/hijos, fragmentos y límites antes de publicar.

`from html` propone record ordinario Nu `{schema:"r3viewer.html.v1", source:{kind,raw,encoding,decode}, origin:{...}, document:{kind:"document",children:[...],quirks}, diagnostics:[...]}`. `source.raw` es UN campo separado string exacto para input Unicode o binary exacto para input bytes; nunca se repite por nodo ni se reconstruye del DOM. Exportar nombres cualificados y attrs como listas de records preserva namespaces/orden; children anidado conserva texto mixto. No tabla plana. raw nativo open/http continúa independiente y no pasa por conversor. Esta forma concreta refina la propuesta canónica de documento/nodos anidados; el spike no establecía un schema productivo incompatible.

Export consume HtmlProduct sin otro propietario: mueve raw a Value y no clona el input completo; nodos/textos/copias inevitables del pool al Value se financian por capacities reales coexistentes. Un input ya recibido como Value pertenece inicialmente a Nu y no se anuncia como memoria preexistente controlada. Viewer de archivo/URL usa HtmlProduct acreditado; pipeline de record sigue siendo datos salvo `--format html` explícito y schema validado. Un envelope transformado se valida como valor recibido, no se reabre el archivo ni se reparsea raw para sustituir su árbol. Su origen/procedencia se marca Provided; los números del record no acreditan propietario ni spans. Esa entrada mantiene DOM y raw separados y no promete que DOM recibido proceda de raw recibido.

HTML5 inserta/repara nodos, normaliza nombres/atributos, resuelve entidades y descarta attrs duplicados según parser. El árbol conserva TODO el DOM del perfil, incluidos comentarios, doctype, script/style text, head y templates, aunque la lectura filtre contenido no visual. No promete preservar spelling/quotes/attrs duplicados originales en DOM: están en source.raw. No inferir `implicit=true/false` por callback ni asignar rangos originales inventados. Un nodo queda `ParsedUnattributed` respecto a source; Document/fragmentos generados tienen identidad de modelo, no bytes literales. La presencia de html/head/body implícitos sí es parte del árbol esperado.

## Perfil estático y frontera HTML5

html5ever0.40.1/markup5ever0.40.0 son fuentes adquiridas/verificadas para investigación, aún sin dependencia/lock producto. Usar esa candidata fijada, ParseOpts con scripting_enabled=false y drop_doctype=false; no from_utf8 (Utf8LossyDecoder). No JS, CSS, custom-element reactions, ejecución de eventos, formularios activos ni DOM dinámico de navegador.

Templates son fragmentos inertes. Fijar allow_declarative_shadow_roots=false explícito: shadowrootmode/attrs y template fragment íntegros quedan en árbol/inspección, sin attach silencioso ni composed-tree/CSS/slotting. View identifica contenido template/shadow disponible en estructura; no afirma que el lector dibuje el shadow DOM como un navegador. Namespaces SVG/MathML se conservan completos; eso no habilita MathML render, matemáticas/Mermaid heurísticos ni documentos anidados.

Riesgo candidato H-API01: el callback selectedcontent default y el camino de cierres implícitos de la candidata pueden omitir el resultado estático obligatorio. La obligación ya está FIJADA antes de runtime: selectedness única final y contenido clonado según el contrato R2 siguiente, iguales con cierres explícitos/implícitos. No se ajusta a las capacidades del parser. Tras reproducción contra el oráculo fijo se elegirá finalización estática acotada o parche mínimo del parser si necesario; ambos han de producir el mismo resultado. El warning/API no demuestra por sí solo un defecto ejecutado ni prescribe la técnica. Ningún default no-op permite aceptar un árbol incompleto como correcto. No se añade widget dinámico, JS ni CSS.

## Fuente, encoding, origen y base

Unicode Nu ya está decodificado: conservar string recibido (BOM, CRLF incluidos) y encoding=UnicodeProvided; no reinterpretarlo por meta/header. Bytes: conservar original, elegir decoder siguiendo algoritmo WHATWG fijado (BOM, metadatos de transporte, prescan/meta, fallback y confianza/restart), registrar encoding/autoridad/replacements y texto Unicode derivado. Decoder debe adquirirse/fijarse antes implementación; encoding_rs es sólo candidato sin versión nueva recomendada. UTF inválido reemplazado al decodificar queda diagnosticado, con raw intacto; no llamar al texto resultante original bytes. Parsing normaliza HTML sobre texto derivado, sin modificar raw.

Origen distingue Unknown / Provided / Observed con evidencia: local path metadata no autoriza reabrir; base suministrada es Provided; finalURL sólo Observed por transporte propio RV401/recibo real. Nu0.115.1 PipelineMetadata tiene FilePath/content_type/custom. HTTP response_to_buffer crea http_response{status,headers,urls}; NO aporta campo final_url. Conservar esa metadata como evidencia recibida, no inventar finalURL por último urls. Si final/base no se acreditan, Unknown y `--base` explícita como fallback; no recortar el requisito de URL final que el transporte viewer deberá acreditar. Todas URLs, incluyendo origin, quedan inertes hasta acción.

Base efectiva conserva fallback + primera base[href] en orden DOM + resultado/diagnóstico. Resolver esa primera contra fallback; inválida/data/javascript vuelve a fallback sin elegir una segunda base. `--base` fija fallback Provided, no borra <base>. URL absoluta base puede resolverse aun con origen Unknown; relativa sin fallback queda Unresolved. Función URL pura, sin IO, conserva literal atributo y destino resultante por separado. Fragmentos/ids usan dueño DOM real y ancla estable; duplicados muestran candidatos explícitos paginados64. RV403 resolverá destino y preparará adaptador antes commit de historia; error/cancel conserva origen/posición. No abrir JavaScript/data HTML/scheme ejecutable. PDF/imágenes/HTML van por contenido al adaptador correspondiente, no por extensión fingida.

## Vista compartida RV402/403

Adaptador DOM->modelo común con sidecar NodeID/campo/offset DOM, nunca string Markdown. Orden final reparado, headings/paragraph/br/hr; estilos strong/em/del/blockquote; ul/ol/dl; pre/code con whitespace; anchors/links; imágenes/figure/caption; tablas. Conservar rowspan/colspan/caption y orden de celdas: simple va a layout común, compleja muestra lectura por filas/celdas con spans identificados; no perder asociaciones ni fingir grid soportado. Search/índice/folds/history/layout usan identidad semántica, incluyendo contenido de details plegado. Head/script/style/template no se vuelven prosa; DOM y raw permiten inspección. Hidden produce marcador/acceso estructural, CSS no se aplica; inline sigue legible, details incluye contenido o referencia explícita. Terminal controla proyección de controles, no emite escapes de entrada.

Q24: controles readonly, sin escribir estado ni submit. Checkbox checked por presencia (checked="false" sigue presente); disabled/readonly se identifican. Radio/select tienen snapshot efectivo inicial fijado en R2, separado de atributos originales y visible en lector/conversor. Mostrar etiquetas/type y valores no sensibles, textarea, opciones y botones sin activación de formulario; password no muestra value en lectura (DOM/raw conservados). Nada ejecuta onclick/autofocus ni carga action. Audio/video/iframe/canvas se identifican con alternativa; no reproducción/docs anidados. Imágenes y cualquier secundario remoto aparecen pendiente con alt/title/URL; carga sólo por acción explícita, nunca parser/nu conversor/inline implícito. No añade carga agrupada/persistencia por dominio/autenticación/artículo.

DOM text carece de spans originales garantizados: relaciones literales son NoLiteral/ParsedUnattributed. Una coincidencia DOM no salta a un byte raw imaginado ni se acredita ExactSource por igualdad de bytes. Inspector ofrece DOM owner/campo, raw fuente completa y encoding visible; Source muestra texto decodificado como tal y bytes originales mediante representación de bytes disponible, conservando retorno al ancla DOM. UTF/source mapping necesitará decoder receipt real, no line callback ni búsquedas aproximadas. Markdown wire/perfiles actuales no aceptan automáticamente este sidecar: delta HTML producer/quarantine/anchor/role revisado antes implementación, sin reutilizar perfiles cerrados por etiqueta.

## Cuotas y cancelación reales propuestas

Mantener candidatos de límites actuales: raw128MiB, Unicode derivado128MiB, arena DOM64MiB,1M registros, profundidad64 contando Document/implicit/template edges. Son caps con error completo visible, no promesa de aceptar cualquier entrada de ese tamaño. Presupuesto simultáneo incluye capacities reales de nodos, edges, attrs, pool/text, reparaciones/realloc old+new, stack/finalizer, diagnostics y receipts/headers compilados. Export/modelo nuevo coexisten bajo presupuesto de construcción64MiB compartido en host, no dos allowances independientes; raw transferido conserva recibo fuente separado128MiB. Historial sólo anchors/owner retenido, no copias DOM completas por entrada. Diagnóstico conserva total/counts y página64, sin mensajes ilimitados ni truncar árbol silenciosamente.

TreeSink no retorna Result para crear handles: cada mutación/alloc valida Work/cap/cancel ANTES cambiar árbol. Rechazo usa abort privado tipado dentro catch_unwind del worker seguro Rust; sólo ese payload se convierte en Limit/Cancelled, otro panic es WorkerFailed. No inventar NodeID/sentinel para seguir parseando. En panic=abort también es fracaso completo por proceso, nunca resultado parcial. Parsing completo dentro subprocess propio, START antes fuente/parser tras Job verificable; biblioteca/tokenizer/atoms/allocator opacos no se atribuyen a arena64. Windows committed-memory limit512MiB por proceso ya existe en worker_process, no RSS/aggregate ni sandbox. Controller controla plazo parse10s y cleanup2s incluso entre callbacks; child+Job+pipes/threads retenidos hasta wait/close/join/JobActive0, Pending impide siguiente spawn. Unix containment debe verificarse aparte; no usar parsing in-process para aparentar compatibilidad ausente.

Fuente entra incremental4096, reader/hashing/decoder/projection/export comprueban token cancel. Perfil HTMLWork candidato512Mi unidades de trabajo para lectura/decoder/sink/quarantine/export controlados, acumulado por preparación/captura/finalización/export real; no es512MiB de memoria ni aumento del DocumentWork8Mi/D1/layout existentes. Sin reinicio por chunk/page ni allowance por componente, sin presentar coste wrapper como CPU total html5ever. Se medirá y congelará recibo exacto por sizeof/copias antes del código; exact-/1 debe rechazar sin publicación. Procesamiento library entre callbacks no tiene contador CPU exacto: deadline/containment externo, no garantía por chunk. No publicar DOM/Value antes End+quarantine+worker reap. Cancel/error mantiene vista/source actual y no retorna árbol parcial.

Nu PluginCommand run y serializer son fronteras distintas: Value se mueve al header y SDK write_response/flush serializa antes destruirlo; MsgPackSerializer usa write_named, no se afirma codec-buffer/RSS total. Implementar puente opt-in de ResponseLease por CallId real que conserve recibos de Value/raw y slot de invocación HASTA retorno de write_response/flush/Drop físico (también Error). SDK actual no expone ese guard a PluginCommand; es delta interno aditivo necesario, no API Nu pública/ABI nuevo ni modificación comportamiento encoder. Work/body/ArcHeaders/captures del guard serán sizeof compilados antes copia/spawn. Una llamada HTML admitida por service; concurrente recibe Busy y no crea otro parser. Writer arbitrariamente bloqueado no es interrumpible por SDK polling: propietario queda Pending y bloquea nueva conversión, no se mata Nu ajeno ni se presenta timeout como cleanup. El llamador puede conservar/duplicar el Value recibido: memoria de Nu posterior a transferencia está fuera del ledger servicio; no promesa de cota global de shell.

## Delta normativo R2: snapshot readonly obligatorio (HD-R1-01)

Este apartado tiene precedencia sobre ambigüedades R1 y no depende de aprobar una salida candidata. R1/oráculos/fixtures permanecen congelados. Es estado inicial pasivo de HTML recibido, no interacción ni promesa de un navegador dinámico. Evaluar fuente a EOF con árbol reparado y defaults declarados; publicar conjuntamente árbol, estado efectivo y procedencia después de finalización/quarantine. No inferir éxito por conservar attrs.

Definición del perfil estático: para controles conectados al Document, resolver form owner HTML (incluido form explícito por ID/orden y casos parser-associated que requieren recibo real de construcción), árbol y name no vacío; agrupar radios sólo cuando coinciden esas autoridades. Aplicar defaults checked y exclusión del grupo: el último radio checked incorporado al grupo deja los anteriores false. Para fixtures normales sin reparación que cambie grupos coincide con orden documental, pero no se sustituye universalmente la asociación/captura real por un sort final de NodeID. Grupos sin checked quedan todos false; distinto owner/tree/name o name vacío no se fusionan. Disabled no elimina un radio del grupo. Checkbox mantiene checked por presencia. Sin dirty estado de usuario, clicks, focus, validación activa ni envío. Controles dentro de fragmentos template inertes conservan attrs/estructura y se identifican como inertes; no se conectan ni activan para cambiar grupos del documento.

Cada select determina su lista de opciones HTML, sin atravesar select anidado/datalist ni las otras exclusiones normativas. Estado default de option parte de presencia selected. Sin multiple, prevalece la última seleccionada; si ninguna, tamaño visual 1 selecciona primera opción habilitada (disabled propio/optgroup), y tamaño mayor no fuerza ninguna. Si todas deshabilitadas, ninguna por fallback; una selected explícita deshabilitada sí sigue seleccionada. Con multiple se mantienen todas las seleccionadas y no se introduce fallback. Size se interpreta según entero no negativo y default normativo; no copiar IDL size=0 para fingir display size=0 cuando attr está ausente. Attrs originales selected no se borran ni añaden para codificar el resultado.

selectedcontent conectado y habilitado en select simple contiene clones estáticos profundos de LOS HIJOS de la opción efectiva, sin wrapper option; si no hay selección, vacío. La habilitación se resuelve por cadena de ancestros: no puede cruzar option/selectedcontent ni un segundo select. Un selectedcontent deshabilitado conserva su contenido autoral sin update; multiple tampoco actualiza sus selectedcontent. No simular tareas/eventos/microtasks: la obligación aquí es el snapshot final equivalente de estos elementos pasivos, terminado antes de publicar. La misma selección y el mismo árbol resultan con option cerrada explícita o implícitamente. El contenido autoral reemplazado permanece en raw original, no en children final del selectedcontent.

Clone preserva orden, tipo, namespace/local/prefix, lista de atributos y texto, y duplica subárboles/template_contents mediante fragmentos propios. Cada nodo clonado tiene identidad nueva local al mismo propietario, padre nuevo y derivación DerivativeClone{origin_node,selected_option,selectedcontent}; no comparte edges/padres ni se hace pasar por nodo literal fuente. Los nodos originales conservan ParsedUnattributed; nadie recibe span byteExact de parser callbacks. Relaciones de derivación señalan nodos reales acreditados, no ordinal privado. Clone y fragmento transitorio se cargan por tamaño/capacity compilados y Work ANTES crear/copiar; old content más candidate coexisten hasta Drop real. IDs, edges, attrs/text, snapshot ControlState, receipt de derivación, stack, rollback y export Nu se incluyen en los caps R1 (64MiB/1M/depth64/HTMLWork512Mi); no allowance adicional por finalizer. Cancel/límite durante clone no publica árbol ni estado parciales.

La representación compartida incorpora sidecar ControlState keyed por NodeID real: checkedness efectiva para checkbox/radio; selectedness por option y referencias de opción/lista para select; flags de inert/disabled y procedencia de inicialización. Envelope Nu document añade lista control_state keyed por IDs exportados y cada node exporta id/provenance, de modo que attrs default y estado efectivo no se confundan. Esos IDs del envelope siguen siendo datos Provided a revalidar: no construyen autoridad interna. Lectura obtiene resumen readonly de ese mismo sidecar; el conversor exporta tanto attrs como estado, sin fabricar checked/selected content attrs. Registro/envelope restante R1 sin cambios.

Frontera técnica abierta, obligación cerrada: sink con eventos de estado suficientes + finalizer acotado puede satisfacerlo; si pierde form association/orden de transiciones o cierres implícitos necesarios, deberá conservar recibos de construcción o usar parche mínimo revisado. Ninguna técnica se acredita aquí ni se elige por salida favorable. Un resultado diferente de H09/H18 R2 será FAIL de contrato aunque el parser explique su limitación. No se exige corregir biblioteca antes de reproducir; se exige no rebajar el resultado cuando se reproduzca.
