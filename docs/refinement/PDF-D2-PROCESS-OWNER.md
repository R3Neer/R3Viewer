# D2 concrete process representation / no policy relaxation

D1 inventory used std::process::Child. Accepted wire requires explicit inherited HANDLE whitelist plus a bootstrap start pipe. No such helper exists in canonical worker_process.rs, and local rust-src is unavailable; do not infer whitelist from std::Command::spawn. Local windows-sys0.61.2 SDK does expose CreateProcessW, STARTUPINFOEXW and PROC_THREAD_ATTRIBUTE_HANDLE_LIST. No sources or SDK will be downloaded/installed.

Proposed implementation representation: closed OwnedPdfProcess with original OwnedHandle process + original primary-thread OwnedHandle + status, all immediately stored in PdfCallPhysical before next fallible call. Use explicit STARTUPINFOEXW attribute HANDLE_LIST containing ONLY inherited startRead/stdinRead/stdoutWrite/stderrWrite. Parent endpoints and Job not inherited. Create suspended; keep primary thread owned, attach/readback SAME PdfOneProcessJob(activeLimit1/512MiB), resume only after verified containment; worker still waits for START on startRead before input/native load. Neither process/thread raw IDs nor names authorize rescue. GetExitCodeProcess is read only after original WaitForSingleObject signals; handle checked closes retain SAME ownership on error. ChildWait means actual process wait, not Drop/OptionNone; active0 and checked Jobclose remain separate.

This changes D1 representation/layout from std Child and invalidates affected core/capsule/captures; it does NOT change actor/wire policy, deadlines, profile, inherited-handle requirement or receipt criteria. Before runtime compile/measure actual new process/attribute/argv/header/captures and exact source/bin. Attribute buffer is aligned and actual capacity funded before Initialize/Update; argv/env/executable UTF16 buffers/source retain original Actor charge. Temporary API structures and partial PROCESS_INFORMATION returns are preadmitted/stored; setup error retains any handles returned. No generic destructor produces Joined proof. Acquire/panic injection follows each actual stored resource.

Legacy hooks continue retaining existing std Child/Connection/Pending/Parts with existing signatures/profiles. This new process type is exclusively the PDF profile, no global rewrite of ChildJob. Final D2 requires decoy inheritable-handle own negative, explicit four-handle whitelist own positive, bootstrap withheld native-call0, attach/readback faults/ActiveLimit1 and physical waits/closes under original request/cleanup clocks. D1 declarations cannot prove those controls.
