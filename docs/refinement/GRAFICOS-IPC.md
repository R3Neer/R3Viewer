# Gráficos: snapshot, protocolo y controlador — propuesta R3

2026-10-05. Siguiente corte privado del diseño G2 revisado, antes de integrar PNG. No nuevo sprint ni cambio de CLI. Base producto b39d690, raster por filas R2 aprobado y Sixel R2 todavía en revisión. No importar Sixel como aprobado por esta propuesta. Se reutilizan las cotas y perfiles de GRAFICOS-PNG/G2/SIXEL-G2; este corte prueba su composición por IPC y presupuestos agregados. No emite comandos de terminal ni implementa cache persistente.

## Resultado comprobable

Un controlador Rust adquiere una PNG local sintética una sola vez, mantiene bytes inmutables, autoriza un descriptor, entrega los mismos bytes a un worker propio ya contenido y recibe un cuerpo validado. Publica Ready exclusivamente después de End, EOF y exit exitoso y reap; una cancelación o generación obsoleta invalida también un resultado íntegro. Ningún byte worker se escribe a terminal. Datos binarios pueden contener ESC; sólo Sixel trata el cuerpo como lenguaje ASCII restringido. Un resultado final es payload tipado con descriptor y referencia del origen, no un String ANSI.

Paquete privado .tmp/graphics-ipc-gate-r1, fuentes/lock/targets propios; main/Cargo/CLI producción sin modificaciones. Copiar exactamente código del raster aprobado; Sixel sólo si su R2 completa revisión y AE. Separar módulos snapshot, descriptor, wire, ledger, controller, worker y validator; no reutilizar el R3V1 de valores Nu ni el R3ST de estructura para imágenes. Windows primero; Unsupported Unix permanece explícito y no publica Ready de un worker sin contención validada.

## Adquisición y propiedad

Supervisor posee desde nacimiento su proceso hijo y handles, lectores y escritor; bootstrap no libera codec antes de Job512MiB KillOnClose y readback de configuración/asignación. Todos los lectores/escritor tienen guardia de cleanup desde spawn, deadline único y colas/capturas limitadas. Setup parcial, pánico, error de canal o logging no puede omitir kill/wait/cierre. Usar handles propios; nunca matar por nombre ni process group global. ReapTicket Pending/Reaped/Failed se conserva, sin reutilizar worker anterior durante Pending/Failed.

La adquisición también ocurre fuera del hilo UI. En el gate, controlador/supervisor es un proceso propio; el watchdog externo puede terminarlo si File::open/read bloquean. En integración futura no transportar ese bloqueo a un thread abandonado: deberá mantenerse supervisor cancelable recogible. Windows OpenOptions read-only share_mode(FILE_SHARE_READ) excluye write/delete; registrar y probar escritor ya abierto incompatible y escritor posterior. Si apertura incompatible: IO1 según contrato, no mezclar snapshots. Leer tamaño real con máximo64MiB, crecimiento/capacidad preadmitidos, extra-byte detecta exceso; hashing incremental de esos mismos bytes; metadatos no sustituyen bytes. El gate no acepta snapshots Unix ni proclama atomicidad portable. N/D/F sólo tienen cabecera33B y no reciben hash de cuerpo; este gate se limita a raster R.

Source Arc<[u8]> inmutable parent y copia worker se contabilizan ambos, incluida transición Vec→Arc y old+new/capacity. Sin memoria zero-copy presumida. SHA256 candidato sha2 con versión exacta y lock nuevo tras consultar fuente primaria; no algoritmo propio. Worker vuelve a calcular hash al terminar recepción antes de PNG scanner; no abre ruta ni URL ni carga recursos. descriptor se entrega separado de source y contiene dimensiones declaradas; parser confirma IHDR exacto, no confianza en parent simplemente porque se ejecuta en el mismo usuario.

## Wire R3GI versión1

Enteros little-endian y discriminantes fijos; no JSON ni serialización de longitud libre. Bootstrap byte propio sólo antes del protocolo. Request empieza magic8B R3GIREQ1, request-id u64, generation u64, snapshotSHA256[32], backend u8 (KittyRGBA1/iTermPNG2/Sixel3), profile-version u16, sourceW/H u32, cropX/Y/W/H u32, targetW/H u32, scaleNum/Den u32, geometryW/H u16, alpha-policy u8, matteRGB[3], theme-id u8, sourceLength u64; tamaño fijo calculado por constante/test, no padding C. Raster fit/crop producido por parent y validado worker; denominador no cero, todos productos/sumas checked. Unknown backend/version/alpha/theme o tamaño inválido se rechaza antes de source alloc. request-id/generation u64 se incrementan checked, overflow cierra sesión en lugar de reutilizar identidad.

Perfil incluye versión exacta del encoder/codec fijada por executable package manifest; profile-version selecciona un perfil autorizado dentro de ese paquete, nunca nombre/version suministrado libremente. theme-id referencia paleta efectiva inmutable del request; matte explícito evita usar sólo nombre de tema como identidad. geometry=0/0 significa desconocida sólo para backend sin necesidad de píxel físico del gate; una componente cero sin la otra inválida. Si integración requiere geometría física para transmitir, no inventarla a partir de este campo.

Request sourceLength bytes exactos seguido EndRequest magic8B y SHA256[32], después stdin EOF. Worker rechaza truncado/trailing y no empieza decode antes del EOF confirmado. Hash source en header/end/calculado deben coincidir. Canal writer en paralelo con reader, acotado y cancelable, para evitar deadlock pipe. EOF no provoca codec cuando bootstrap/asignación falló. Source hasta64MiB; source pixels≤16M y target/crop válidos antes de reserva raster. Dimensiones target no mayores que límite zoom contratado ni superiores a límites admitidos de raster/payload; no se adopta zoom de8 como cap físico absoluto sin ledger.

Response magic8B R3GIRES1, descriptor exacto completo (incl sourceLength), status u8: Payload1, Reference2, Failure3. Payload añade bodyLength u64, body bytes y EndResponse magic8B + request-id u64 + SHA256body[32]. Reference/Failure añaden diagnostic-code u16 de catálogo cerrado (sin texto arbitrario), EndResponse/request-id y hash del cuerpo vacío. Response header longitud fija según status, se rechaza status/descriptor discrepante antes de body allocation/read. No Progress frame en esta versión; timeout no depende de actividad. Stderr jamás es control ni diagnostico visual libre: capture64KiB límite total, exceso falla y limpia.

Parent deriva límites antes de reservar: Kitty longitud exactamente4*dw*dh y base64+overhead futuro≤32MiB; iTerm body PNG generado más base64/overhead≤32MiB; Sixel cuerpo+framing futuro≤32MiB. Overhead conservador del framing definido en la prueba; futuro framing deberá acreditar su cota antes de adoptar pack. Cumplir32MiB no exime ledger256MiB de requested heap objetivo ni origen16M/RGBA64MiB. End único, hash propio body, EOF real sin bytes extra, worker exit0 y wait requerido. Reference status no se convierte en imagen vacía ni éxito visual. Failure, protocolo inválido, timeout, exit no0 o cancel preservan referencia original con diagnóstico local0; IO adquisición fatal1; CtrlC130 son responsabilidad de presentación futura, el gate observa clasificaciones internas distintas.

## Ledger y cache

Ledger lógico agregado de requested heap256MiB aplica simultáneamente parent+worker: source/copies/Arc transition, header/stderr/queues/reader/writer buffers, scanner/inflater scratch, fila/Adam7/index prepass, Sixel256*width, output-count/no outputalloc, emitted body, parent receive and old+new, validation scratch. Libro es explícito, no medición RSS ni Job conjunto: native/inflater internal allocations deben tener cotas auditable en perfil o quedar como reserva conservadora justificada; no aceptar una suma que los omite. Todos Vec try_reserve_exact previos y capacidad real comprobada; error reserva es Reference sin pánico. Reservas no duplicadas, devolución RAII; comparar ledger teórico+trazas y muestras committed parent/hijo separadas. El gate debe fijar esos números antes de su ejecución, con adversario si cambia el contrato.

Para primer gate no cache: un resultado y una petición activa, una pendiente latest-wins. Invalidar antigua generación, cerrar worker antiguo y reap antes del siguiente. Retener payload anterior durante cálculo nuevo sólo si ledger admite old+new; si no, soltar representación propia y mantener referencia. La integración posterior de LRU64MiB por clave completa se revisa por delta; no cerrar G6 desde ausencia de cache.

## Validación y aceptación independiente

Kitty: exactRGBA/descriptor/longitud sin parsear escapes binarios. iTerm: scanner PNG generado restringido, CRC/Adler/IEND+EOF, dimensiones exactas, perfil sin ancillary/animation no autorizada y decode/row quotas; si comprobar cuerpo requiere segundo decode entra ledger/deadline. Sixel: validador estricto independiente de encoder según diseño aprobado, no ESC/C0/C1 ni framing, bandas y máscara final y paleta/coords/RLE acotados. Cualquier verificación incompleta impide Ready.

Congelar expectativas antes de outputs: PNG pequeños oracle de pixels, colores/crop/alpha, grandes16M viewport pequeño, Kitty binaryESC permitido; Sixel OSC52/DCS/terminador/IDs hostiles rechazados; iTerm PNG con dimensiones falsas/CRC/Adler/trailing/APNG. Cada campo descriptor incorrecto con hash/generation correctos, unknown enums/profile, length exact/+1/u64max/overflow, truncación por sección, End ausente/doble/hashes incorrectos, EOFextra/exitno0/alive-after-End, parentcancel-after-End y stale-beforepublish: cero Ready, cero terminalbytes, reap antes de siguiente. Bounds256MiB/32MiB±1, reservefault con límites previos, cumulativestderr/queue/deadline/setupfallos. Cancel durante acquire/send/decode/count/emit/receive/validate; kill during native blocked stub es separado de codec real.

Registrar deadline de experimento10s total por request y cancel→supervisor observado/reap1s con timings por fase; no presentarlos como SLA UI250ms hasta integración TUI. Fuente mutation con writerprevio/posterior, snapshotHash/codechash manifest, mismo path con nuevo contenido fuera del snapshot y descriptor idéntico except hash; no cache hit alegado. Builds/checks pertinentes, freeze manifest exacto, revisión de código y AE independiente; intentos fallidos conservados. No terminal/framing/visual/inline/cache/Unix ni G2 completo aprobado desde este gate.

## Delta normativo R2: grafo y prueba externa de cierre (G2IPC01)

Esta sección precisa y prevalece sobre referencias ambiguas a padre/supervisor/watchdog anteriores. Grafo del gate: H harness/autoridad externa → C controlador propio → D worker codec propio. H es único actor que puede publicar Ready y completar el receipt global; C sólo entrega candidato en cuarentena. H crea Job exterior J, KillOnClose+ProcessMemoryLimit512MiB y sin breakaway permitido, asigna C y verifica antes de liberar su bootstrap. D hereda J desde su creación; C no crea procesos adicionales. H conserva J y handle propio de C hasta cierre de todos los actores. C conserva su ChildD, pipes y JobD opcional de límite independiente; asignación/readback preceden codec igual que antes. H no se termina como mecanismo de cancelar un request: cierra/termina J, espera y sigue vivo para comprobar recibos. La muerte total de H mata su Job, pero no genera Reaped ni permite otro request desde un actor desaparecido.

Antes de liberar bootstrapD, C envía por canal autenticado propio nonce + valor numérico de su handleD retenido; no duplica nada hacia H. H posee processhandleC con PROCESS_DUP_HANDLE desde spawn y llama DuplicateHandle con SourceProcess=C, TargetProcess=GetCurrentProcess(H), derechos SYNCHRONIZE|PROCESS_QUERY_LIMITED_INFORMATION|PROCESS_TERMINATE, no herencia y sin DUPLICATE_CLOSE_SOURCE. El out-handle se inicializa null y, en éxito, se convierte inmediatamente a OwnedHandle local antes de cualquier validación o logging. Sólo H crea handles en su tabla; no hay duplicado remoto desconocido si C muere entre llamada y mensaje. C conserva fuentehandleD hasta ACK y después su Child normal sigue poseyéndolo para wait. Si C muere antes del pull, H sólo recibe fallo sin handle creado; si muere después, H tiene guardia propia y cierra/espera D. No hay pushdup ni tabla remota por especificar.

H valida que el handle sea de proceso (GetProcessId exitoso), PID distinto de C y de H, membership en J propio y acceso query/wait esperado. J fija ActiveProcessLimit=2 para C+D, sin breakaway ni otros descendientes; H mismo está fueraJ. No OpenProcess por PID global ni validación a partir de nombres. Nonce/canal exclusivo evita entregar el valor desde D/stdoutpayload; sólo controlC autorizado. Un handle de archivo, handle inexistente, de C/H, de proceso fueraJ o duplicación fallida se rechaza y libera localmente antes de ACK; D no recibe START. C no cierra ni reutiliza fuentehandleD antes de ACK, evitando raza con reutilización de tabla. H retiene guardiaD desde éxito DuplicateHandle hasta cierre final, incluso si falla validación/ACK/readback. Si control entrega duplicado lógico de una transferencia anterior, no crear nueva guarda: el único envío esperado por estado es una vez, extra invalida request. BootstrapD bloqueado no permite creación de más procesos.

Whitelist de handles heredados evita que D conserve writers de controlH, handleJob o processhandleH/C. C necesita sólo su stdoutcontrol y pipesD; H no transfiere su propio processhandle hacia C. Derechos y handles heredados exactos se contrastan con controles antes del gate. C no tiene API de apertura por ruta/proceso suministrado desde D. Job/Dwait/query requieren pruebas de derecho efectivas, no sólo números en tipos.

Si C muere antes de transferir D, H termina J y espera su handleC. Además QueryInformationJobObject de J retenido debe confirmar ActiveProcesses=0 antes de receipt global, mediante polling acotado hasta deadline de cleanup; sólo cuenta miembros de este Job propio, no enumeración por nombres/PID globales. CloseJob no sustituye esa prueba: usar TerminateJobObject manteniendo handleJ hasta observar0. Si D fue transferido, H espera también su handle conocido. En camino normal C declara waitD/exit0 y H lo contrasta por handleD propio; H espera Cexit0, observa ActiveProcesses0 y cierra handlesJ/C/D antes del commit. Warnings/errores de query/dup/transfer/wait/close se fijan irreversiblemente; Failed/Pending significa cero Ready y no siguiente proceso/parser. La prueba de conjunto0 cubre el intervalo de spawnD aún no transferido; no acredita un exitcodeD desconocido en camino normal, que exige la transferencia y wait individual.

Acquisición puede bloquear C antes de D; H watchdog permanece libre. D sólo recibe bytes, no ruta, como R1. Si C todavía conserva source y H recibe copia para cuarentena, ambas entran ledger; H no retiene tercera copia implícita. Los overheads H/C/controlJob y buffers/handoff pertenecen al mismo objetivo agregado256MiB; fixedsubreservas+native/runtime margin se concretan antes de implementar/ejecutar, con revisión delta si no se logra la cota. Job512MiB por proceso sigue siendo protección distinta, no256MiB total.

Controles independientes nuevos: terminar C antes de D, después de spawn antes de transferencia/ack, después de START, send/decode/receive/validate y después de End; fallos DuplicateHandle/transfer/ack/assign/readback/query; ActiveProcesses retrasado/error y waitD fallido. H debe observar exit de todos sus procesos, miembros0 y cierres, sin rescate exterior para PASS. Intento siguiente bloqueado mientras global receipt Pending/Failed. En stub bloqueado identificar C por adquisición o D por codec, sin alegar codec real bloqueado.

## Delta normativo R2: único commit final (G2IPC02)

Candidate/quarantine puede contener body válido y End, pero nunca Ready. ReceiptProcess acredita wait individual; ReceiptIO separado exige stdinwriter terminado sin write/flush/close/panic, stdoutreader EOF sin trailing/error, stderrreader EOF y≤64KiB sin read/UTF8/overflow/error, threads join exitosos, capturas y colas drainadas dentro de cuota y cleanup completo. C y H tienen esos recibos para sus propios canales; no se interpreta stdoutEOF como stderrEOF. Si stderr son bytes de diagnóstico privado, su UTF8 inválido es fallo cerrado y no se convierte a texto con sustituciones para aprobar.

H tiene punto de commit único, serializado con cambio de generación y latch de cancelación: descriptor/hash/body/End válidos, receiptsProcess de C/D exit0, receiptsIO de ambos cerrados correctamente, prueba JActiveProcesses0, handles cerrados sin error, request/generation vigente y cancel no latched. Cancel o nueva generación que se fijó antes de este punto gana; después del commit la presentación futura puede retirar el resultado ante cancel de sesión sin confundir ese evento con commit del trabajo. La comprobación y publicación usan la misma región crítica/estado serial del controladorH; no checkcancel antes de join seguido de publicación independiente. Error final fija Reference/Failure sin publicación previa y ledger libera cuarentena.

Ensayos deterministas con barrera antes de informar ReceiptIO final: stdoutEnd/EOF+exit0 ya observados pero stderr retenido; overflow64KiB+1, readerror/panic reader, write/flush/close/panic writer y latecancel/generationchange antescommit. Siempre cero Ready mientras falta recibo y después del error. Control positivo de stderr tardío válido recibe exactamente un Ready únicamente tras release/join/cierre/quiescence. Encender Progress no renueva deadline ni puede saltar la barrera. No terminalbytes en ningún caso de este gate.


## Respuesta a revisión R2

G2IPC01 ownership duplicado remoto: retirado por completo push C→H. H hace pull hacia su tabla y retiene OwnedHandle antes de validar; C sólo publica un valor de handle fuente que sigue poseyendo. Fallos antes de pull no crean objeto desconocido en H y fallos después dejan un guard conocido. Añadir controles muerte C antes/después pull/antesACK, error DuplicateHandle y tipos/membership/rights inválidos; detectar leaks por conteos propios sin rescate paraPASS. ActiveProcesses0 sigue prueba del conjunto durante intervalo desconocido pero no reemplaza wait individual para un camino Ready. G2IPC02 se conserva cerrada en diseño según revisión anterior; nuevo adversario debe comprobar delta y coherencia completa.
