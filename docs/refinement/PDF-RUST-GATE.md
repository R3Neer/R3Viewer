# PDF: siguiente gate Rust privado, propuesta R1

Recomiendo comenzar con una FFI mínima propia sobre ABI chromium/7881 y con RAII tipado; mantener pdfium-render0.9.4 como alternativa evaluable mediante parche local revisado. El parche del loader del wrapper es pequeño, pero no basta por sí solo para cumplir el contrato de este corte: sus rutas altas añaden form-fill, singleton global y extracción textual no acotada. La recomendación es para el siguiente experimento privado, no una adopción definitiva de arquitectura ni un recorte del PDF completo.

Este documento sólo refina. No se ejecutó PDFium ni un PDF, ni Rust/Cargo, ni se modificaron producción, snapshots shell/PDF anteriores, perfiles, CI o remoto. Se leyeron PDF-G0, PDF-G1 y docs/research/PDF_G1_SPIKE.md (la ruta research/PDF_G1_SPIKE.md abreviada del encargo corresponde a docs/research). G1 R2 ctypes recibió revisión y AE verdes sólo para su corte Windows y corpus pequeño; no acredita Rust ni todo G1.

## Comparación

| Aspecto | Wrapper0.9.4 parcheado | FFI mínima7881 propia |
|---|---|---|
| Loader | bind_to_library usa Library::new. Parche interno cfg(windows) con os::windows::Library::load_with_flags(path,0x900).into(); resto de targets fuera de este gate. DynamicPdfiumBindings es pub(crate): no hay inyección externa directa de Library cargada sin parche. | LoadLibraryExW0x900 o libloading Windows exacto fijado; resolver sólo whitelist de símbolos del gate; conservar library mientras existan punteros/handles. |
| Bitmap externo | PdfBitmap::from_bytes es público, checked stride/height y préstamo mutable; render_into_bitmap permite reutilizarlo. Tras drop bitmap se usa el buffer propio. as_raw_bytes devuelve Vec copiada, aunque su comentario diga referencia: no zero-copy. | CreateEx sobre slice previamente dimensionado checked, Bitmap RAII con préstamo mutable; cerrar antes de leer/publicar buffer. Control de cuota explícito idéntico. |
| Source lifetime | load_pdf_from_byte_slice liga documento al préstamo de self y bytes. No usar load_from_file/reader ni clon silencioso del snapshot. | Document<'bytes,'api> retiene préstamos; scopes anidados evitan estructura autorreferencial y liberan documento antes de snapshot/api. |
| Global lifetime | Primer Pdfium::new/new_with_config pone bindings en OnceCell global. Pdfium::drop sólo libera proveedor de fuentes; no DestroyLibrary/unload/reset. No múltiples instancias como política de reset. | Library/init explícitos por proceso; InitGuard llama DestroyLibrary después de todos los handles y sólo si Init completó. Library se descarga después. |
| Formularios | PdfDocument::from_pdfium inicia PdfForm; éste llama FPDFDOC_InitFormFillEnvironment incluso antes de comprobar form type. Config de render tiene do_render_form_data=true por defecto. Desactivar render_form_data no evita inicializar form-fill. Callbacks None/V8false no prueban cumplimiento de «sin API form-fill». | No resolver/invocar APIs form-fill, acciones, JS ni callbacks de usuario. Links futuros sólo metadatos/destinos inertes. |
| Texto | text.all→inside_rect→GetBoundedText, reserva toda región y unwrap_or_default. chars() colecta todos los índices. No sirven como extracción completa de capa acotada ni como diagnóstico NoText. bindings de bajo nivel existen, pero acceso de objetos al global es privado. | CountChars/GetUnicode/GetText y mapping se pueden invocar por tramos con estados y cuotas propios, sin reserva de página entera. Más obligaciones unsafe/ABI propias. |
| Serialización | thread_safe es default y BINDINGS no es aislamiento. Defaults false +pdfium_7881; un único thread nativo. No confiar en trait Send/Sync del binding para API thread-safe. | Tipos !Send/!Sync por marcador Rc; único thread del worker y supervisor externo. Menos API, más RAII auditado propio. |

La ruta wrapper completa necesitaría, además del loader, modo document sin form-fill, vía textual raw acotada que no colapse errores, y política explícita de global lifetime. Alternativa intermedia: conservar Box<dyn PdfiumLibraryBindings> devuelta por loader parcheado y usar sólo bindings bajos con RAII propio, sin Pdfium::new ni objetos altos. Evita OnceCell/form-init pero carga el catálogo grande de símbolos y arrastra dependencia extensa; ya es prácticamente un adaptador FFI. No recomendar implementar un trait enorme externo sólo para eludir pub(crate).

El costo de la FFI mínima es real: firmas/estructuras inseguras y cierre parcial propios. Para Windows x64, extern "system" respeta header FPDF_CALLCONV; verificar size/alignment/offsets repr(C), incluyendo TODOS los campos de FPDF_LIBRARY_CONFIG con version2 y posteriores cero. No extrapolar calling convention o layout a x86/Unix. Emitir lista exacta de símbolos, errores y funciones destructoras desde los headers fijados; revisión independiente antes de ejecución.

## Gate experimental propuesto: Rust privado sobre7881

Un único paquete fuera de Cargo raíz, lock fijado, fuentes vendorizadas o cache/hash exactos, DLL/headers/avisos intactos. FFI mínima recomendada, sin producción. Comparar wrapper sólo si el adversario acepta primero su delta y su política de lifetime; no preparar dos implementaciones simultáneas obligatorias. El propósito inicial es acreditar Rust/RAII/source lifetime/buffer externo y diagnóstico textual, no integración terminal ni render gráfico común.

1. Congelar expectativas independientes y corpus sintético antes de ejecutar. Reusar fixtures G1 exactas sin modificar; agregar pequeñas fixtures propias separadas para UTF16/astral/combining/ligadura/generated newline, texto repetido entre tramos, texto fuera CropBox y scan sin capa, rotaciones0/90/180/270, MediaBox≠CropBox/offset crop, protected-empty-password failure y security error cuando exista fixture acreditada. Verificar estructura y resultado esperado con fuentes distintas del candidato; Poppler es contraste, no identidad de pixels. No corpus Clases todavía.
2. Padre adquiere snapshot binario hash/descriptor/generación y tamaño antes del spawn. Hijo retenido por handle se bloquea antes de DLL/Init/documento; Job propio KillOnClose+committed512MiB configurado/asignado/readback antes de bootstrap. Lectores/stdin acotados, try/finally desde Popen, cleanup intenta todos los pasos aunque falle evidencia. No nombres de procesos ni señales ajenas. G1 setup-faults R2 pasan a regresión, sin convertir bootstrap hold en native-blocked.
3. Source≤1MiB, páginas≤256, ventana visible positiva≤1024×1024 BGRA/BGRx y bitmap≤4MiB, texto≤65536 índices PDF/página y UTF8≤256KiB/página, chunk≤1024 unidades/indexes según API, salida controlJSON≤64KiB; plazo total10s por ensayo y cleanup propio acotado separado. Son techos iniciales candidatos del experimento, NO cuotas finales de producto. Acreditar cada límite y límite+1, arithmetic overflow, fallos try_reserve y no asignación previa al check. Contabilizar snapshot+bitmap+texto+mapping+salida juntos; límite Job no reemplaza reservas. FPDFText_LoadPage/LoadPage pueden asignar internamente antes de CountChars, contenidas por OS, no calificarlas prealloc gratuitas.
4. Handles tipados NonNull con préstamos a Api/padre, sin Clone, !Send/!Sync. Orden normal/error/panic: bitmap/text-page→page→document→DestroyLibrary→Library; bitmap antes del buffer mutable, documento antes de source. Cada init/carga parcial registra recursos adquiridos; no DestroyLibrary si no se inicializó. Drop sin logging/alloc/fallo que impida otros cierres. Fallos en cada punto y pruebas compile-fail del préstamo deben quedar reviewables. Killing child durante llamada bloqueada recupera proceso; no pretende ejecutar Drop nativo ni demostrar RAII en ese caso.
5. Render de ventana estrictamente visible con transform/clipping/rotación/matte explícitos; validar width/height positivos finitos, conversions c_int, stride alineado checked, bytes checked y cuota ANTES del Vec/CreateEx. Guardas separadas alrededor del slice; leer/publicar después de bitmap drop. No as_raw_bytes/as_rgba_bytes/image natural. Cache no se implementa aquí: identidad incluye page physical/scale/crop/rotation/matte/hash/generation y futura carga común PDF+PNG sigue pendiente. No certificar equivalencia visible sólo por guardas o checksum uniforme.
6. Texto: CountChars -1 es error, cero sólo NoText cuando extracción satisfactoria completa. Header7881 documenta GetText como UCS-2 y que ignora caracteres sin representación; no asumir GetText contiene todo Unicode por mencionar UTF16 en G0. Experimentar con GetUnicode(u32) por índice como ruta completa candidata y GetText(count+1) como contraste/mapping, verificar scalar válido, cero/unmapped/control/generated y astral. Fijar identidad de capa por método sin mezclar resultados que dupliquen caracteres. GetText return dentro de capacidad+terminador; no avanzar PDF index por longitud UTF8/UTF16 devuelta. GetCharIndexFromTextIndex y viceversa pueden dar -1 y deben validarse, no prometer mapping por sumas.
7. Decodificador UTF16 incremental probado aparte con chunks deterministas, high surrogate pendiente y límite UTF8 antes de append; pareja rota/no scalar no produce U+FFFD buscable. Astral omitido por API es cobertura incompleta, no NoText. Estados Complete/NoText/Error/Limit/Unmapped/InvalidUnicode distintos. Mapping por scalar/tramo guarda índice PDF o absent explícito; match atraviesa tramos contiguos válidos, nunca páginas/huecos. Repeticiones n/N requieren intervalo UTF8, página/hash/generación; bboxes sólo con mapping y transform acreditados. Fuera CropBox pertenece a capa y puede encontrarse, sin inventar highlight visible.
8. Cancel/timeout externo: controles bootstrap/no-release, posterior a load y en fases extracción/render, hijo expected/reaped y readers terminados antes de PASS. Stub nativo controlado bloqueado demuestra supervisor frente a llamada FFI sin retorno; se etiqueta stub, NO PDFium bloqueado. Un caso PDFium realmente bloqueado no está acreditado ni garantizado por fixture; requiere evidencia futura distinta. No otro thread para llamar PDFium a «desbloquear». Respuesta parcial/EOF temprano/hash/generation/request tardíos invalidan publicación.
9. Congelar candidato/fuente/lock/DLL/headers/fixtures/oracle/raw/logs/manifest y diff antes/después; autor no se acepta a sí mismo. Adversario distinto y AE distinto ejecutan independientes. Fallos nuevos se conservan y fijan antes del candidato siguiente. Sólo tras verde acotado se puede proponer integración G2/protocolo/cache/lazy/scheduler/historial/inline; no ejecutar esos pasos automáticamente.

## Evidencia faltante y salida del gate

G1 ctypes no demuestra código Rust, estructuras Rust, préstamo o RAII, wrapper parcheado, Unicode/mapping, rotación/crop, protected/crypto, stress/cuotas reales máximas ni native-blocked. Ni crosscheck ni este diseño prueban runtime Linux/macOS. Rust gate sólo puede cerrar lo que sus fixtures y controles acrediten, y debe listar los restantes con precisión.

PDF completo conserva RV204 y contrato G0: páginas físicas/lazy/historial, búsqueda literal documento bajo demanda y estados incompletos, raster visible/fallback textual etiquetado/scan, links/bookmarks inertes, cifrado diagnóstico, snapshot binario/URLs futura, identidad/cache común y scheduler, Job/supervisor, terminal q/C130/restauración y QA visual. Las cuotas finales requieren corpus amplio/stress/medición propia y runtime nativo por plataforma. Cualquier reducción para este ensayo es frontera de experimento, no reducción de aceptación ni nuevo sprint. Integración shell permanece congelada sin cambios.
